# Safe diagnostics (TASK-022 accepted)

## Privacy boundary

`DiagnosticEvent` carries only a fixed event kind, generated session/correlation identifiers, pipeline stage and error-category enums. Do not add source/translated text, credentials, URLs, profile names, window titles, provider configuration, exception objects or arbitrary property bags to this contract.

`RedactingDiagnosticSink` rebuilds each Serilog event before forwarding it to its destination. It drops the incoming message template, exception (including message/stack/data/inner exceptions), trace/span values and all properties except strictly typed, defined kind/stage/category enums and nonempty GUID session/correlation identifiers. Strings claiming to be these metadata types are rejected. Unknown events use `Unspecified`. Only trusted generated identifiers belong in the identifier fields.

This is deliberate data minimization, not a pattern-only secret detector: arbitrary keys, auth headers, URL/query values, provider configuration, known secret strings and OCR/translation content are removed wholesale rather than guessed, shortened or partially masked. The boundary does not invoke an untrusted property's `ToString`, traverse exception data, or keep a second copy of known secret values. The intended topology is one such boundary before every real destination; raw loggers/sinks must not be exposed to application code.

Destination exceptions are contained and counted atomically. Failure reporting must not recursively log the exception or private file path.

`BufferedDiagnosticWriter` projects typed events once before admission into a bounded channel (default 256, maximum 4096). Admission never waits for a sink: full/closed admission increments an atomic drop counter. One background worker owns sink creation, writing and disposal; those failures are counted without retaining exception details. The recent-event ring stores at most 100 immutable JSON strings by default (maximum 1000), independently of disk availability. Asynchronous disposal completes admission, drains accepted entries and disposes the sink once, including repeated calls. Shutdown still relies on the selected sink's synchronous operations returning; this is not a timeout guarantee for an indefinitely hung sink.

## Dependencies and verification

`DiagnosticWriters.CreateProduction` now composes the bounded writer with a private Serilog JSON file logger under `%LOCALAPPDATA%/GameLingoAI/logs` by default. It rolls daily and by size (default 1 MiB), retaining seven files. Validated limits are 1–31 files and 1 KiB–16 MiB per rolling threshold. Serilog checks size before writing: a file can exceed the threshold by one content-free event (under 1 KiB for the current contract). The factory allows an explicit directory for isolated tests/synthetic mode. Retention touches only its matching `diagnostic-*.jsonl` files. Count/size enforcement assumes the filesystem permits rotation/deletion; disk/permission failures must remain visible as degraded diagnostics, not a successful retention guarantee.

`CreateDevelopment` configures Console and Debug JSON sinks behind the same typed asynchronous boundary. Each destination is wrapped with Serilog's `Fallible` configuration and a `DiagnosticFailureCounter`; notifications increment an atomic count without rendering/retaining the sender, message, events or exception. `BufferedDiagnosticWriter.Failures` includes these notifications as well as boundary exceptions (a notification count, not a count of uniquely lost events). Never enable raw `SelfLog` output containing paths or exception text.

The file suite exercises three reopen cycles, small-threshold rotation, count/size checks, correlation, unrelated-file preservation and a directory blocked by a file. It also captures actual development Console JSON and injects a throwing Console writer: Serilog's swallowed failure is counted, recent events survive and the secret exception marker is absent.

The redaction suite also sends all 500 hostile events through actual Console, File and Debug sinks after the central boundary. A test-only `ITextFormatter` observes the real Debug sink's supplied buffer after `JsonFormatter` writes it; this is precisely the string the pinned sink passes to `Debug.Write` ([v3.0.0 source](https://raw.githubusercontent.com/serilog/serilog-sinks-debug/v3.0.0/src/Serilog.Sinks.Debug/Sinks/Debug/DebugSink.cs)). All 500 payloads must be byte-identical across destinations, retain correlation and exclude hostile content. This tests the Debug payload, not a Visual Studio output window or OS debugger transport. It uses no debugger attachment, process memory access or hooks. Application factories expose only the typed writer; source audit confirms no raw application Serilog logger or SelfLog path bypasses that boundary.

A real Windows retention-failure test holds an old matching synthetic log open without delete sharing, then writes 100 events with a one-file policy and 1 KiB rolling threshold. The internal failure listener reports deletion failures, recent events remain available and the directory stays at no more than the one undeletable old file plus the current retained file. Reopening after releasing the lock restores the configured one-file count. A locked file cannot be physically removed: health is degraded until that external lock is released, rather than claiming the configured count was met during the lock. The test uses an isolated temporary directory.

Central package versions: Serilog 4.3.0, Console 6.1.1, Debug 3.0.0, File 7.0.0. These dependencies are required by TASK-022, not a new telemetry service. References: [Serilog](https://www.nuget.org/packages/Serilog/4.3.0), [file sink rotation documentation](https://github.com/serilog/serilog-sinks-file), [console sink](https://www.nuget.org/packages/Serilog.Sinks.Console/6.1.1), [debug sink](https://www.nuget.org/packages/Serilog.Sinks.Debug/3.0.0).

The `diagnostic redaction` smoke suite generates 500 hostile events including secret text, auth headers, credential-bearing URLs, nested provider structures, exceptions/inner exceptions/data, Unicode and objects whose string rendering throws. It checks sanitized JSON absence plus retained correlation/stage context, forged/invalid metadata rejection, and 1,000 concurrent contained sink failures. Together with actual destination tests, factory/lifecycle tests and support-bundle tests, these cover the boundary, destinations and application composition.

## Session event integration

Core now defines `IDiagnosticEvents` without any Serilog dependency. `SessionController` accepts this optional nonblocking boundary and emits typed starting/running/paused/stopped/fault notifications plus capture/translation/presentation completion and OCR/translation failure events. Capture, translation and presentation preserve the same pipeline correlation identifier. No frame, text, profile/provider name or exception object crosses this boundary. Admission rejection is allowed; exceptions from a faulty implementation are contained without recursive logging. The destination must honor the nonblocking contract.

`SessionViewModel` forwards an injected boundary to the controller; `ErrorReporter` emits a content-free command-failure notification while preserving the existing safe UI message. Session lifecycle tests record actual events, check shared flow identifiers, and then repeat 20 start/stop cycles with a throwing diagnostics implementation.

## Application lifetime

`App` registers an app-owned `ApplicationDiagnostics` instance as `IDiagnosticEvents`. No destination is opened while validating DI or constructing the window. Main-window `Loaded` asynchronously reads configuration, starts Release file logging or Debug Console/Debug logging and emits `ApplicationStarted`; `--synthetic-test` always uses its isolated temporary `logs` directory. Only the saved retention number (1–30) is passed to the factory, never the configuration object. Invalid values or a failed read fall back to seven files and increment diagnostic failures. `IncludeRecognizedText` never enables content logging. Retention changes apply at next application launch, not by changing the active session profile. Accepted window close cancels and awaits this initialization before draining services; WPF `OnExit` cancels/disposes the startup token source. A local CA1001 suppression documents this framework-owned lifetime rather than suppressing analyzer checks globally.

Normal close stops hotkeys, session, profiles and database operations before awaiting diagnostics drain. Instance registration avoids synchronous DI disposal of an async-only writer. Repeated start/close is idempotent, and a late Loaded event cannot restart a closed owner. `OnExit` requests best-effort shutdown for abnormal paths; forced process termination cannot guarantee a flush. Logger construction failures are counted without interrupting application startup. Lifecycle tests verify lazy start, one disposal, command-error content exclusion, drain, repeated/early shutdown and failed creation. Native full-app launch/close passed with the diagnostics UI test described above.

## Aggregate metrics

`SessionViewModel.GetDiagnosticMetrics` exposes the controller's content-free session counters and six stage timings. Stage counts are cumulative for that session; p50/p95 describe the most recent (up to) 256 samples per stage, not the entire session distribution. Stage lists now have read-only wrappers. Drop/cache/error counters are atomic individually; this is a diagnostic sample, not a transactionally simultaneous snapshot of every worker.

`CurrentProcessMetrics.SampleAsync` uses a cancellable background task and a disposed `Process.GetCurrentProcess()` handle to read this application's private bytes, working set, cumulative CPU milliseconds and handle count, plus managed bytes and total allocated bytes. It never enumerates other processes, reads memory contents or collects dumps. Unavailable native counters remain null rather than reporting false zeroes; CPU is cumulative time, not utilization percent. `ApplicationDiagnostics.SnapshotMetricsAsync` combines these counters with the supplied session snapshot and log health at a UTC timestamp for the diagnostics page and bundle preview.

Tests perform 32 concurrent real own-process samples, pre-cancellation, aggregate snapshot composition and 2,000 concurrent controller snapshot reads across 20 restart cycles, checking percentile order and read-only stage collections. Resource values vary by host and are not fixed performance thresholds.

## Diagnostics page

The Diagnostics navigation entry now displays a dedicated view with an explicit refresh button and read-only metric/event JSON boxes. The page explains null counters, cumulative CPU, the latency sample window and local-only privacy boundaries. It reads the same app-owned diagnostics instance used by the session and command-error paths. It does not automatically poll, write files, export or send network requests.

To export, prepare a preview, inspect all four displayed file names and contents, enter an absolute local `.zip` destination and check the review/approval box. Only then is Export available. A fresh preview, refresh or path edit invalidates approval; each export attempt that reaches the writer consumes approval. Export uses the frozen preview and captures its destination at admission. A successful write displays a local-save confirmation. Cancel applies to the active refresh, preview or export, and app close drains the active work. Commands cannot overlap. Tests perform a real ViewModel-driven ZIP export and compare every archived entry with the displayed preview, including missing-preview refusal, destination-change invalidation and consumed approval. Native keyboard/layout acceptance and manual ZIP inspection passed as recorded above.

`DiagnosticsViewModel` serializes only typed metrics and reads the already sanitized recent-event ring. Duplicate refreshes are rejected while busy. A failed refresh retains the previous visible snapshot and uses the existing safe error reporter. Application close cancels and drains the active refresh before stopping other services; late completion cannot overwrite the closed view. Tests cover these behaviors and JSON visibility, while the existing WPF shell construction test loads the view through normal DI. Native visual, keyboard and full-app lifecycle acceptance passed with the completed export controls.

## Support bundle core

`SupportBundlePreview.Create` freezes four UTF-8 payloads: `versions.json` (numeric application/runtime versions and config schema only), `metrics.json` (typed aggregate snapshot, at most six stages), `events.jsonl` (at most the latest 100 recent events), and `manifest.json` (all entry names plus size/SHA-256 of the three payloads). The manifest does not recursively hash itself. Total payload size is capped at 512 KiB. The preview exposes a read-only dictionary of immutable strings; later mutation of the source stages/events cannot change the archive.

Events are projected again from bounded JSON (16 KiB per input, depth eight): only canonical enum names, generated GUID context and parsed UTC timestamp survive. Arbitrary text, message templates, exception data, URLs and properties never become archive content. Malformed/oversized events become `Unspecified`; GUID fields remain trusted application-generated identifiers. Export never reads old disk logs, configuration files, databases, screenshots, OCR text or dumps.

`ExportAsync` requires explicit consent, rejects UNC paths, writes a unique local partial file, then commits with a non-overwriting move. It reports only fixed entry names, checks cancellation during writing and before commit, and deletes its own partial on cancellation/failure. Filesystem denial of cleanup still propagates as failure rather than a false success. Tests compare every archive entry byte-for-byte as UTF-8 text with the preview, inject hostile event content, mutate source collections, reject unconfirmed export, preserve an existing destination and cancel after the first entry with no partial remaining. Automated tests additionally recompute SHA-256 and byte lengths from actual ZIP entries, verify exact UTF-8 bytes and require unique/complete manifest names. Manual artifact inspection passed as recorded above.
